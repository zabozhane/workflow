# Проверка, ревью, отчёт, push

Работай в копии задачи, а не в основной папке проекта.

## 1. До кода

- **Список пар для отчёта:** по одной на каждый пункт приёмки с экраном —
  роль, запись, экран, ширина.
- **Снимки «было»** — один раз, ровно по этому списку, до первой правки.
  Забыл — сними с основной ветки в отдельной копии, а не «по памяти».
- **Сценарий приёмки** по пунктам «Готово, когда», если в проекте есть чем
  их запускать ({{инструмент сценариев}}). После этого сценарий под код не
  правится: не проходит — чинится код.
- **Тесты до кода** — для правил и расчётов: тест → прогон, красное → коммит
  с тестом → код → зелёное. Красное подтверждается только так; `git stash`
  и ручной откат правки для этого не использовать.

## 2. Два режима проверок

Качество держит один полный прогон на последнем коммите, а не их число.

- **Пока пишешь и чинишь** — узко: тест изменённого файла, типы, один
  сценарий на одной ширине. То, чего правка не касается, не перезапускай.
- **Ворота** — один раз, на коммите, который идёт в отчёт:
  `{{тесты}}`, `{{линтер}}`, `{{типы}}`, `{{сборка}}`, все сценарии на всех
  ширинах ({{какие ширины}}). Появился коммит после ворот — ворота заново.

## 3. Своя проверка в запущенном проекте

- Запусти проект: `{{команда}}`, адрес `{{адрес}}`, учётки — `{{где}}`.
- Пройди каждый пункт «Готово, когда» сам. Открой 2–3 снимка: зелёный
  прогон с пустым или недогруженным экраном доказательством не считается.
- **«Как поедет»:** выключатели задачи выключены — нового нет, старое
  работает; роль без права получает отказ; каждая роль в своих правах.
- **Сверка с макетом части** — сам, до проверяющего. Отличие — либо «придёт
  в такой-то части», либо «решено владельцем», либо ошибка. Ошибки чини.
- Пройди 2–3 соседних экрана из «Что может задеть».

## 4. Ревью пачкой

Когда свои сценарии зелёные, запусти одновременно на одном коммите:

- проверяющего `verifier` — дай ему шаблон, путь к макету и название задачи;
  не давай код, diff и свои объяснения;
- ревью кода (`/code-review`) и ревью безопасности (`/security-review`);
- {{второе ревью, если есть инструмент}}.

Дождись всех, собери находки в один список, почини разом, проверяя узко. Не
чини находку первого ревью, пока не пришли остальные.

Перед этим — границы: `git diff --name-only origin/{{main}}...HEAD` против
строки «Границы правки». Файл вне границ — откати или спроси владельца.
Строка, которая не объясняется задачей, откатывается.

После общей правки — ворота {{и полное второе ревью}} на последнем коммите.
Проверяющий повторно — только если правка задела пункт, который он не
принял. Не больше двух его кругов: на третьем покажи владельцу оба ответа.
Третий круг ворот с новыми блокирующими находками — остановись и покажи
владельцу, что не сходится.

## 5. Отчёт владельцу

Задача с экраном — страницей, картинки внутри. Сверху вниз:

1. Итог одной-двумя фразами. Вопросы, если остались.
2. **Было → стало** — пара снимков на каждый пункт приёмки с экраном. Без
   пар отчёт не готов.
3. «Макет части → результат» и список отличий с пометкой у каждого.
4. Пункты «Готово, когда»: прошёл / не прошёл; вердикт проверяющего.
5. «Как поедет»: что увидел по каждому из трёх пунктов.
6. Проверки с числами — на каком коммите; вердикты ревью; что не исправлено.
7. Границы: всё внутри заявленных путей или список исключений. Находки
   рядом. Всё, что убрано или отключено по ходу, — отдельной строкой.
8. «Смотрит владелец»; что не проверено и почему; выключатели.

В тред — 3–4 строки и ссылка. В конце один вопрос: «Пушить?».

## 6. После «пушь» — без вопросов

```bash
git fetch origin {{main}}
git push -u origin <ветка>
{{команда создания PR, если PR есть}}
```

- Ветка отстала — `git merge origin/{{main}}` в ветку, затем ворота заново.
- Следи за проверками сам, владельца не жди. Красное — открой журнал,
  почини, прогони то же локально, новый коммит, push.
- Заканчивай, только когда {{влито и выкладка проверена}} либо нужно
  решение владельца. «Жду, напиши мне» — не окончание.
- После вливания: убери копию задачи (чисто и всё отправлено — без
  `--force`), запиши итог в {{трекер}}, запусти следующую часть.

Чего агент не делает сам: {{не одобряет и не вливает PR / другое}}; на
рабочую среду — только по отдельному слову владельца.
