# Шаблон порядка работы с агентом — для любого проекта

Порядок вырос на рабочем проекте и обобщён: в нём нет ничего про конкретный
продукт. Схема такая: владелец участвует в начале (вопросы и «да» на шаблон)
и в конце («пушь»), остальное агент делает и проверяет сам.

## Что в папке

| Файл | Куда положить в новом проекте | Зачем |
|---|---|---|
| `CLAUDE.md.template` | `<проект>/CLAUDE.md` | главные правила: когда звать владельца, цепочка задачи, границы, Git, проверки, среды |
| `skills/task-flow/SKILL.md` | `<проект>/.claude/skills/task-flow/SKILL.md` | от слов владельца до подтверждённого шаблона и карточки: разбор, гриллинг, шаблон, подтверждение |
| `skills/task-check/SKILL.md` | `<проект>/.claude/skills/task-check/SKILL.md` | проверка, ревью, отчёт, push, доведение до вливания |
| `agents/verifier.md` | `<проект>/.claude/agents/verifier.md` | независимый проверяющий: принимает по экрану, кода не видит |
| `README.md` | не копировать | эта инструкция |

## Что агент подтянет сам, а что нет

Claude Code сам, без настройки, читает из папки проекта:

- `CLAUDE.md` — в начале каждой сессии;
- `.claude/skills/*/SKILL.md` — показывает скиллы в списке и загружает по надобности;
- `.claude/agents/*.md` — помощники, которых можно вызвать.

Сам он **не** подтянет:

- то, что в шаблоне стоит в `{{двойных скобках}}`: команды проверок, имена
  веток, адреса сред, где лежат задачи. Это заполняется один раз при установке;
- инструменты: способ запустить проект локально, сценарии для экранов,
  второе ревью. Их нужно иметь или завести;
- правила из этой папки, пока файлы не лежат в самом проекте.

## Установка: один раз на проект

Проще всего поручить установку агенту. Склонируйте этот репозиторий рядом с
проектами (например, в `~/Projects/workflow`), откройте сессию в папке
нового проекта и отправьте, подставив свой путь:

```text
Установи в этот проект порядок работы из папки ~/Projects/workflow.

1. Прочитай там README.md и все файлы шаблона.
2. Изучи этот проект: чем запускается, чем тестируется, какие есть линтер, типы, сборка, CI, как устроены ветки и вливание, есть ли уже CLAUDE.md или AGENTS.md.
3. Задай мне одним сообщением вопросы из раздела «Вопросы владельцу» в README — только те, на которые не нашёл ответ в проекте. К каждому — что ты нашёл и что предлагаешь.
4. После моих ответов разложи файлы по местам из таблицы и замени всё в {{двойных скобках}}. Чего в проекте нет (например, тестовой среды) — убери соответствующие строки, а не оставляй пустые скобки. Существующий CLAUDE.md не затирай: покажи мне, что с чем объединяешь.
5. В конце покажи список созданных файлов, что заполнено, что убрано и что осталось сделать мне руками. Ничего не коммить и не пушь.
```

Руками то же самое: скопировать четыре файла по таблице и пройти поиском по
`{{` — заполнить или удалить каждое место.

## Вопросы владельцу

На них агент не ответит сам — это ваши решения.

1. **Где живут задачи?** Трекер (какой, как к нему обращаться) или просто
   файл `TASKS.md` в проекте.
2. **Что значит «выложить»?** Есть ли тестовая среда и рабочая, что
   происходит при вливании в основную ветку: ничего, автовыкладка на тест,
   сразу в работу.
3. **На что всегда нужно ваше слово?** Обычный набор: рабочая среда, деньги
   и платежи, удаление данных, внешние отправки (письма, SMS, платные
   сервисы), необратимые команды Git. Что добавить или убрать.
4. **Есть ли в проекте экраны?** Если да — нужны макет до кода, сценарии
   приёмки и проверяющий. Если это библиотека, скрипт или бэкенд без
   интерфейса — эти части убираются.
5. **Работаете один или с командой?** Нужны ли PR и ревью, или вливаете
   сами. Есть ли чужие зоны, куда агенту нельзя.
6. **Чем запускать и смотреть локально?** Команда запуска, адрес, тестовые
   учётки для ролей.
7. **Нужно ли второе ревью другой моделью?** Если есть инструмент —
   подключить; нет — остаётся ревью Claude.

## Что нужно иметь, чтобы порядок работал

| Нужно | Без этого | Обязательно? |
|---|---|---|
| Команды проверок: тесты, линтер, типы, сборка | агент не может сказать «проверено» | да |
| Способ запустить проект локально | нет своей проверки и проверяющего | да, если есть экраны |
| Отдельная копия на задачу (`git worktree`) | задачи в параллельных тредах мешают друг другу | да, если тредов больше одного |
| Сценарии для экранов (Playwright или аналог) | приёмка только глазами проверяющего и вашими | желательно |
| Место для отчётов и снимков (`.reports/`) | доказательства остаются в треде | да |
| Второе ревью | одно ревью Claude | по желанию |
| Хук-сторож на опасные команды | запреты держатся только на тексте | по желанию |

Сторож в шаблон не включён: он пишется под запреты конкретного проекта.
Это хук `PreToolUse` в `.claude/settings.json`, который читает команду и
отказывает или просит подтверждения.

Гриллинг в начале задачи идёт через skill `grilling:grilling` или
`grill-me:grill-me` — это отдельные плагины Claude Code. Не установлены —
агент ведёт разговор по тем же правилам сам, они записаны в `task-flow`.

## Сколько брать

- **Маленький проект, один человек, без экранов:** только `CLAUDE.md` и
  `task-flow`. Из `CLAUDE.md` убрать среды, макеты и проверяющего.
- **Проект с интерфейсом:** все четыре файла.
- **Проект с командой, деньгами или рабочими данными:** все четыре файла,
  плюс свои разделы в `CLAUDE.md`: чужие зоны, правило для денег («расчёт
  до/после и „да“ владельца до кода»), выключатели по средам.

## После установки

- Первую задачу проведите целиком и посмотрите, где агент спотыкался: какие
  кнопки разрешений всплывали, о чём он спрашивал зря, что вы нашли сами
  после его «готово». Каждое такое место — одна строка в `CLAUDE.md` или
  скилл.
- Правила добавляйте по фактам, а не заранее.
- Эти файлы обычно лежат вне Git проекта или в нём — решите сразу. Вне Git
  их нужно сохранять отдельно.
